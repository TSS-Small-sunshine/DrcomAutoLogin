# 03 - 使用与排错

> ⚠️ **适用范围**：本项目默认配置与实测环境为**福建农业职业技术学院**校园网；其它学校需自行确认网关地址与协议。

这份文档分 5 部分：

1. 界面逐项说明（每个框、每个开关是干嘛的）
2. 运营商后缀怎么选（**选错一定登录失败**）
3. 首次使用步骤
4. 「仅在指定 WiFi 下生效」怎么用
5. 常见问题 + 安全说明

## 一、界面逐项说明

App 打开后从上到下依次是 5 个区域：**连接状态 → 账号配置 → 自动化 → 按钮 → 运行日志**。

### 1）连接状态（最上面，只读）

这一区显示 App 最近一次检查的结果，**每 2 秒自动刷新**，你不用手动点。

| 显示项 | 含义 | 可能出现的值 |
| --- | --- | --- |
| **网络：** | App 能不能连上校园网认证服务器 | `可达` / `不可达` / `未知` |
| **在线状态：** | 网关认为你当前是否已登录在线 | `已在线`（绿色）/ `未在线`（红色）/ `未知`（灰色） |
| **上次检查：** | 上一次执行检查的时间 | `2026-09-20 11:30:05` 这种格式；从没检查过是 `—` |
| **上次错误：** | 上一次出错的原因 | 平时是 `—`；出错时显示具体原因 |
| **当前 WiFi：** | 手机当前连着的 WiFi 名称（SSID） | WiFi 名字；没连 WiFi 或没给定位权限时是 `—` |

**怎么看这一区：**

- `网络：可达` + `在线状态：已在线` = 一切正常，你正在校园网上。
- `网络：可达` + `在线状态：未在线` = 能连上网关，但你还没登录。App 会自动帮你登，登不上就会在「上次错误」里写明原因。
- `网络：不可达` = **手机根本连不到认证服务器**，通常是因为你不在校园网（见后面的常见问题第 1 条）。
- `未知` = 还没检查过，或者刚启动还没出结果。

### 2）账号配置

| 字段 | 说明 | 默认值 |
| --- | --- | --- |
| **认证服务器** | 校园网认证网关的地址（你学校的那台服务器 IP） | `172.16.80.3` |
| **端口** | 登录接口用的端口 | `801` |
| **上网账号** | 你的学号或手机号（**只填账号本身，不要自己加 `@yd` 这种后缀**） | 空 |
| **运营商** | 账号类型，下拉选择（详见第二节） | `校园用户（无后缀）` |
| **密码** | 你的上网密码，输入时显示为圆点 | 空 |

填写规则（App 会自动校验）：

- **认证服务器留空**时，会**自动使用默认值 `172.16.80.3`**。
- **端口**必须是 1 到 65535 之间的数字，否则点保存时会弹出提示「端口需在 1-65535 之间」，配置不会被保存。
- **上网账号**是整个 App 唯一的必填项。留空点保存会提示「请先填写上网账号」。
- **密码**可以不填，但那样检查时会直接跳过登录并在日志里记一条「密码未设置」。

> 💡 **认证服务器和端口不知道填什么？**
> 默认值 `172.16.80.3` 和 `801` 是 Dr.COM 校园网的常见配置。如果你学校不是这个，问一下同学或网管中心，或者打开电脑浏览器看认证页面跳转的地址（形如 `http://172.16.xxx.xxx:801/eportal/...`），把它填进来。

### 3）自动化

| 开关 / 选项 | 说明 | 默认 |
| --- | --- | --- |
| **自动检查** | 总开关。关掉后 App 不会定期检查（但你手动点「立即登录」仍然有效） | **开** |
| **检查间隔** | 下拉选择：`15 分钟` / `30 分钟` / `60 分钟` / `120 分钟` | `30 分钟` |
| **仅在指定 WiFi 下生效** | 只在这些 WiFi 下才检查。填 WiFi 名字，多个用英文逗号分隔；**留空 = 任何网络都检查** | 空 |
| **常驻通知保活** | 打开后 App 会挂一条常驻通知并监听网络变化（详见 [02 - 国产 ROM 保活指引](02-国产ROM保活指引.md)） | **关**（国产手机建议打开） |

关于「检查间隔」要知道的两件事：

1. 安卓系统对后台定时任务有**强制最小 15 分钟**的限制，所以 `15 分钟` 已经是能给到的最快档位。**更频繁的检查是做不到的**。
2. 检查不是「到点必跑」——系统会挑一个它认为合适的时机执行（可能晚几分钟）。**而且如果手机当时没联网，系统会跳过这次**。

### 4）按钮

| 按钮 | 作用 |
| --- | --- |
| **保存配置** | 把当前页面上的所有设置存下来，并立即生效（会重新安排定时任务、启动/停止保活服务）。**改完任何设置都必须点它，否则不生效。** |
| **立即登录** | 立刻执行一次「查在线 → 没在线就登录」。**它也会先保存当前配置**，所以你可以改完直接点它，不用先点保存。另外它**无视「自动检查」开关**，即使自动检查是关的，手动点它照样执行。 |
| **打开电池优化设置** | 跳转到系统的电池优化页面，让你把本 App 设为「不优化」。跳转失败会提示「无法打开电池优化设置」。 |
| **刷新日志** | 手动刷新下面的日志区（平时它也会每 2 秒自己刷新）。 |
| **清除日志** | 清空日志。**注意：这个操作不可撤销。** |

### 5）运行日志

- 显示**最近 100 行**日志，最新的在最下面（会自动滚到底）。
- 每行格式：`[时间] [级别] 内容`，级别有 `INFO`（正常）、`WARN`（警告）、`ERROR`（错误）。
- 日志文件本身最多保留 **200 行**，超出后自动删掉最老的。

日志里常见的几种内容：

| 日志内容 | 意思 |
| --- | --- |
| `开始检查 (reason=periodic)` | 定时任务触发的检查（`reason` 还会是 `manual` 手动 / `boot` 开机 / `network` 网络恢复） |
| `本机 IP=... MAC=...` | 本次登录要用的本机 IP 和 MAC 地址 |
| `已在线` | 无需登录，一切正常 |
| `网关不可达（可能不在校园网）` | 连不上认证服务器，见常见问题第 1 条 |
| `登录成功: xxx` | 登录成功，`xxx` 是服务器返回的提示 |
| `登录失败: xxx` | 登录失败，`xxx` 是服务器返回的原因 |
| `密码未设置` | 你还没填密码 |
| `自动检查已关闭，跳过` | 「自动检查」开关是关的，本次跳过 |
| `当前 SSID=xxx 不在白名单，跳过本次检查` | WiFi 白名单没匹配上 |
| `无法读取当前 SSID（可能缺少定位权限），继续执行` | 读不到 WiFi 名字，但**不影响登录**，会照常检查 |
| `网络已可用，触发一次登录检查` | WiFi 刚连上，保活服务立刻补了一次检查 |

## 二、运营商后缀怎么选（重点）

Dr.COM 网关要求登录账号带上**运营商后缀**。App 里的「运营商」下拉框就是干这个的，它会把后缀**自动拼到你的账号后面**。

| 下拉选项 | 实际拼出来的账号 | 什么时候选它 |
| --- | --- | --- |
| **校园用户（无后缀）** | 账号**原样**，不加任何东西 | 你用的是**学校自己发的**校园网账号（大多数同学是这种） |
| **移动 @yd** | 账号 + `@yd` | 你的账号是**中国移动**的手机号套餐账号 |
| **电信 @dx** | 账号 + `@dx` | 你的账号是**中国电信**的宽带/手机号账号 |
| **联通 @lt** | 账号 + `@lt` | 你的账号是**中国联通**的账号 |

### 举个例子

假设你的上网账号是 `12345678`：

- 选「校园用户（无后缀）」→ 实际提交的登录账号是 `12345678`
- 选「移动 @yd」→ 实际提交的登录账号是 `12345678@yd`

### ⚠️ 最常见的错误

**❌ 在「上网账号」里自己写了后缀，又在「运营商」里选了一遍。**

比如：账号框里填 `12345678@yd`，运营商又选「移动 @yd」→ 实际提交的是 `12345678@yd@yd` → **必然登录失败**。

**正确做法：账号框里只填账号本身，后缀完全交给下拉框。**

### ⚠️ 第二个常见错误

**后缀选错了。**

比如你其实是校园自建账号，却选了「移动 @yd」→ 提交的账号多了一个 `@yd` → 服务器会说「账号或密码错误」，但**密码其实是对的**，会让人查半天。

**怎么确定自己该选哪个？**

1. 看你办的是哪家运营商的套餐：学校统一发的校园网账号 → 校园用户；移动/电信/联通办的上网账号 → 对应运营商。
2. 如果不确定，**挨个试一遍**，每次点「立即登录」，看日志里哪次出现 `登录成功`。
3. 也可以看电脑上用 Windows 版时填的账号——如果电脑上填的是 `12345678@yd`，那手机上也应该选「移动 @yd」，账号框里填 `12345678`。

## 三、首次使用步骤

照着做，5 分钟搞定。

1. **打开 App**，第一次会弹出通知权限请求 → 点 **`允许`**。
   （如果误点了「不允许」，去 `设置 → 通知 → 应用通知管理` 里补开，否则保活功能不可用。）
2. **填写账号配置**：
   - 认证服务器：默认 `172.16.80.3`（不是你学校的话改成你学校的）
   - 端口：默认 `801`
   - 上网账号：你的学号/手机号（**不加后缀**）
   - 运营商：按第二节选
   - 密码：你的上网密码
3. 点 **`保存配置`**，看到提示「配置已保存」。
4. 点 **`立即登录`**，看到提示「已提交一次登录检查」，然后看「连接状态」区域：
   - 变成 **`在线状态：已在线`**（绿色）→ ✅ 账号密码正确，配置完成。
   - 还是 `未在线`，看 **`上次错误：`** 显示的内容，对照第五节的常见问题排查。
5. **打开「自动检查」开关**，检查间隔保持 `30 分钟`（或按需调整），点 `保存配置`。
6. **打开「常驻通知保活」开关**，点 `保存配置`。通知栏应该出现「Dr.COM 自动登录」的常驻通知。
7. 点 **`打开电池优化设置`**，把本 App 设为 **`不优化`**。
8. **（国产手机必做）** 按 [02 - 国产 ROM 保活指引](02-国产ROM保活指引.md) 配置自启动和管理后台。
9. **（可选）** 配置「仅在指定 WiFi 下生效」，见下一节。
10. 配置完，**锁屏放 30 分钟**，再回来看「上次检查」时间是否更新到最近。是 → 全部搞定 🎉。

## 四、「仅在指定 WiFi 下生效」怎么用

**作用**：让 App 只在你指定的 WiFi 下工作，避免你在宿舍外的公共 WiFi、或者用流量时白白做检查。

### 怎么填

1. 先看 App「连接状态」区域里的 **`当前 WiFi：`** 显示的名字（比如 `CampusNet-2F`）——**这就是你要填的 SSID**。
2. 在「仅在指定 WiFi 下生效」这一栏填入这个名字：
   - 单个 WiFi：`CampusNet-2F`
   - 多个 WiFi：用**英文逗号** `,` 分隔，例如 `CampusNet-2F,CampusNet-3F,Library-WiFi`
   - 冒号、分号、中文逗号 `，` **都不行**，必须是英文半角逗号 `,`。
3. 点 `保存配置`。
4. **首次保存时手机会弹出定位权限请求**，见下面。

### 关于大小写

匹配时是**不区分大小写**的（`campusnet` 和 `CampusNet` 都算匹配上）。不过为了以后自己看日志方便，**建议原样照抄「当前 WiFi」里显示的名字**。

### 关于定位权限（重要）

**Android 10 及以上，读取 WiFi 名字（SSID）必须要有定位权限**，这是安卓系统的规定（因为 WiFi 名字能用来推断你的位置）。

- **第一次点「保存配置」（且这一栏不为空）时**，手机会弹 `允许 Dr.COM 校园网自动登录 访问此设备的位置信息？`
- 点 **`允许`**（选「仅在使用该应用时允许」就够了）。
- **如果点了拒绝**：
  - 会弹提示「权限被拒绝，指定 WiFi / 保活通知可能不可用」
  - 这个 WiFi 过滤功能**自动失效**（读不到 WiFi 名字，App 会记录一条「无法读取当前 SSID」的警告，然后**照常执行登录检查**）
  - **登录功能本身不受任何影响**，只是「只在指定 WiFi 下生效」这一条不再起作用。
- 想事后补开权限：`设置` → `应用` → `应用管理` → `Dr.COM 校园网自动登录` → `权限` → `位置信息` → 允许。

**⚠️ 注意**：定位权限只用来看 WiFi 名字，App **不会**上传或记录你的位置。App 只有一个网络访问权限，没有定位上报。

### 留空呢？

**留空 = 不做任何限制**，任何网络下（WiFi 或流量）到点都会检查一次。这是默认行为，对大多数人来说就够了。

### 一个实用场景

学校有多个 WiFi（宿舍一个、教学楼一个、图书馆一个），你想「只要有校园 WiFi 就自动登录」→ 把这几个名字都用逗号填进去。

## 五、常见问题

### Q1「永远显示网关不可达 / 上次错误：网关不可达（可能不在校园网）」

这是最常见的现象，按顺序查：

1. **你是不是不在校园网范围内？**（回了家、用了流量）→ 这是最正常的原因，回学校连上校园 WiFi 就自动好了。
2. **服务器地址填错了吗？** → 确认「认证服务器」是不是你学校的网关 IP。默认值 `172.16.80.3` 不是所有学校都适用。
3. **手机连的是流量不是 WiFi 吗？** → 看状态区的「当前 WiFi：」，如果是 `—`，说明你现在用的是移动数据，不是 WiFi。
4. **校园 WiFi 连上了但没认证，被网关拦住了吗？** → 打开浏览器随便访问一个网页，看会不会自动跳到认证页面。会跳说明网络通、只是没登录（那 App 应该能处理）；不跳说明你的 WiFi 根本没连上校园网。

### Q2「登录失败：认证失败 / 密码错误 / 账号或密码不正确」

- **账号或密码本身错了** → 在电脑上或用浏览器手动登一次，确认账号密码能登上。
- **运营商后缀选错了**（这是高频原因）→ 见本文第二节，尤其注意**别在账号框里重复写后缀**。
- **账号被运营商/学校停用或欠费** → 联系网管中心。
- 看日志里 `登录失败: xxx` 的 `xxx`，那通常是**服务器返回的原始原因**，比界面上的更有信息量。

### Q3「已在线但仍然断网 / 明明显示在线却打不开网页」

**原因**：网关认为「在线的那个 IP」和你手机现在实际用的 IP 不是同一个。通常发生在你切换过 WiFi、或者手机 IP 变了之后。

**处理**：

1. **关掉 WiFi 再打开**（最有效，会重新拿 IP 并重新认证）。
2. 或者：在 App 里点「立即登录」重试一次。
3. 还不行就**重启手机**。

### Q4「改了配置没生效」

**必须点「保存配置」。** 只在框里打字、然后切走，是不会保存的。

例外：「立即登录」按钮会**顺带保存**当前配置，所以如果你刚才是用「立即登录」触发的，配置其实已经存了。

改完「检查间隔」或「自动检查」开关后，记得也点一次「保存配置」，让定时任务重新安排。

### Q5「日志在哪？」

- **App 内**：页面最下方的「运行日志」区域（最近 100 行）。
- **文件**：`/data/data/com.drcom.autologin/files/drcom.log`（最多 200 行）。
  - ⚠️ 这是 App 的**私有目录**，**不 root 手机是看不到的**，用普通文件管理器也访问不了。
  - 如果你确实需要导出日志文件，用手机自带的「文件管理 → 应用数据」，或者用电脑 `adb` 工具（需要手机开 USB 调试）。
  - **普通用户直接看 App 里的日志区就够了**，内容是一样的。

### Q6「配置存在哪？换手机要重填吗？」

- 存在 App 私有目录的配置文件里：`/data/data/com.drcom.autologin/shared_prefs/drcom_prefs.xml`。
- **换手机需要重新填一遍**。App 关闭了数据备份功能（为了安全，防止账号密码被系统备份到云端），所以不支持配置迁移。
- 好在就 5 个字段，重填一次不到一分钟。

### Q7「耗电吗？」

很省。它大部分时间都在睡觉，每 30 分钟才醒一次发起两个很小的 HTTP 请求（查一次在线状态，掉线了才登录）。真正耗电的是那条常驻通知和后台服务，一天下来通常不到 1% 的电量。

### Q8「通知栏那条『Dr.COM 自动登录』能关掉吗？」

可以，但**不建议**：

- 关掉的方式是在 App 里关闭「**常驻通知保活**」开关。
- 但这条通知是**用来保命的**——安卓规定前台服务必须有通知，没有通知的服务会被系统优先杀掉。
- 关掉之后，App 被系统清理的概率会明显上升，掉线后可能不会再自动登录。
- 正确做法：**别关，只是把它划掉而已——划掉也没用，它还会回来（因为它是常驻通知）。真正想让它消失就用 App 里的开关。**

## 六、安全说明

### 密码存在哪？

- 存在 App **自己的私有目录**里：`/data/data/com.drcom.autologin/shared_prefs/drcom_prefs.xml`。
- 安卓的**应用沙箱机制**保证：**其他 App 读不到这个文件**（除非手机被 root 过，或者系统本身有漏洞）。
- 密码在这个文件里是**明文**存的（不是加密存的，因为加密需要你额外设一个主密码，对普通用户太麻烦）。所以：**别把 root 过的手机随便借给别人，也别把这个手机备份文件随便发出去。**
- App 关闭了「允许备份」（`android:allowBackup="false"`），所以账号密码**不会被自动同步到云端或备份文件里**。

### 这个工程里有别人的账号密码吗？

**没有。** 本工程是纯源码，**不包含任何硬编码的账号、密码、学号**。你下载到的 APK 里也不会有——**App 里显示的所有账号密码都是你自己填进去的**。

如果你把 APK 分享给同学，他们需要**自己填自己的账号密码**，不会看到你的。

### 网络传输安全吗？

- App 用的是 **HTTP（明文）** 而不是 HTTPS —— 这是**校园网网关本身决定的**，Dr.COM 的认证接口只提供 HTTP，没有加密版本。所以：
  - 账号密码在**校园内网**里是明文传输的；
  - **不要**在公共 WiFi、商场 WiFi 这种陌生网络下使用（虽然那时多半也连不上你学校的网关，本来就不会工作）。
- App 只和「你填的那台认证服务器」通信，**不会上传任何数据到第三方**。

### App 要了哪些权限？

| 权限 | 用来干什么 |
| --- | --- |
| 网络访问（INTERNET） | 访问认证网关，登录用 |
| 网络状态（ACCESS_NETWORK_STATE） | 判断当前有没有网 |
| WiFi 状态（ACCESS_WIFI_STATE） | 读取当前 WiFi 名字（SSID），配合「仅在指定 WiFi 下生效」 |
| 开机自启（RECEIVE_BOOT_COMPLETED） | 开机后自动启动检查和保活 |
| 前台服务（FOREGROUND_SERVICE / SPECIAL_USE） | 挂常驻通知保活 |
| 发送通知（POST_NOTIFICATIONS） | 显示那条常驻保活通知 |
| 忽略电池优化（REQUEST_IGNORE_BATTERY_OPTIMIZATIONS） | 「打开电池优化设置」按钮 |
| 位置信息（ACCESS_FINE_LOCATION / COARSE） | **只**用来读 WiFi 名字（Android 10+ 的系统强制要求），不做任何定位或上报 |

### 你想分享给同学怎么办？

直接把编译好的 `DrcomAutoLogin-debug.apk` 发给他们就行。他们需要：

1. 允许「安装未知来源应用」
2. 自己填自己的账号密码
3. 自己做一遍保活设置（[02 - 国产 ROM 保活指引](02-国产ROM保活指引.md)）

## 七、和 Windows 版的关系

**能用，而且可以同时用。**

- 手机 App 和你电脑上的 Windows 版（`联网_service.py`）用的是**完全相同的 Dr.COM 协议**：
  - 查在线：`GET http://{服务器}/drcom/chkstatus?callback=cb&jsVersion=4.X`
  - 登录：`GET http://{服务器}:{端口}/eportal/portal/login?...`
- 两台设备**不冲突**：网关是按设备的 IP/MAC 分别管理的，手机登手机自己的，电脑登电脑自己的。
- 它们**各管各的**，不会互相顶掉对方的登录状态。

### 两边用同一个账号行吗？

**一般可以。** 学校通常允许同一个账号在多台设备上使用（具体看你们学校的策略），但**有些学校限制「同一账号只能一台设备在线」**——那种情况下，手机登上去会把电脑挤下线，反之亦然。

遇到这种情况的处理办法：**两边只保留一边的自动检查**（比如只在手机上开自动检查，电脑上的关掉），或者干脆两边用不同的账号。

### 两个版本的区别

| | Windows 版 | 安卓版 |
| --- | --- | --- |
| 配置方式 | 网页界面（Web UI） | 手机 App 界面 |
| 开机自启 | 系统服务（NSSM） | 开机广播 + WorkManager |
| 检查间隔 | 可到分钟级，带指数退避 | 最快 15 分钟（系统限制） |
| 网络恢复立即重登 | 支持 | 支持（需开「常驻通知保活」） |
| 额外要做的 | 基本不用 | **必须配国产 ROM 保活** |
